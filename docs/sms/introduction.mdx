Dugble provides one API for sending application-to-person SMS messages. A send request validates the destination and sender ID, calculates the number of billable segments, charges your team wallet, and queues delivery atomically.

## Before you send

You need:

- A Dugble team and a team token with the `sms:send` permission
- An approved sender ID for the `from` value
- Sufficient wallet balance for every message segment
- A supported destination number in E.164 format

<Note>
    Keep team tokens on your server. Never expose a team token in browser or
    mobile application code.
</Note>

## Send an SMS

```bash
curl --request POST \
  --url https://api.dugble.com/sms \
  --header "Authorization: Bearer $DUGBLE_TOKEN" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: <unique-request-key>" \
  --data '{
    "to": "+233201234567",
    "from": "Dugble",
    "body": "Your verification code is 123456.",
    "tags": [
      { "name": "category", "value": "verification" }
    ],
    "metadata": {
      "user_id": "user_42"
    }
  }'
```

A successful request returns `202 Accepted`:

```json
{
    "success": true,
    "data": {
        "object": "sms",
        "id": "49a3999c-0ce1-4ea6-ab68-afcd6dc2e794"
    }
}
```

The ID belongs to Dugble. Store it with your application record so you can retrieve the message later.

## Recipient and content rules

- `to` must be an E.164 number such as `+233201234567`.
- `from` must match an approved sender ID and can be at most 11 characters.
- `body` is required and can contain up to 1,600 Unicode characters.
- Tag names and values may contain letters, numbers, underscores, and dashes and can be up to 256 characters.
- `metadata` must be valid JSON.

## Segments and billing

SMS messages are billed by segment, not by API request. GSM-7 messages generally fit 160 characters in one segment and 153 characters per segment when concatenated. Messages containing characters outside GSM-7 use UCS-2, generally allowing 70 characters in one segment and 67 per concatenated segment.

Dugble calculates encoding units and segment count before charging the team wallet. The retrieve response includes:

- `segments`
- `billing.unit_cost`
- `billing.total_cost`
- `billing.currency`
- `destination.country`

## Track a message

```bash
curl --request GET \
  --url https://api.dugble.com/sms/49a3999c-0ce1-4ea6-ab68-afcd6dc2e794 \
  --header "Authorization: Bearer $DUGBLE_TOKEN"
```
