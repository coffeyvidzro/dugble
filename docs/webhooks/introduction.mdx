Webhooks let an application react to message lifecycle changes without repeatedly polling the Email or SMS retrieve endpoints.

<Warning>
    Customer-configurable outgoing webhooks are currently in development. The
    event names on these pages describe the planned public contract and may
    change before general availability.
</Warning>

## How webhook delivery will work

When outgoing webhooks become available, the flow will be:

<Steps>
    <Step title="Register an HTTPS endpoint">
        Add an endpoint in your Dugble team settings and select the events your
        application needs.
    </Step>
    <Step title="Return a successful response quickly">
        Verify and persist the event, return a `2xx` response, and perform slow
        work asynchronously.
    </Step>
    <Step title="Handle retries and duplicates">
        Webhook delivery is an at-least-once process. Use the event ID as an
        idempotency key before applying side effects.
    </Step>
</Steps>

## Build your endpoint now

You can prepare an endpoint around a small dispatcher:

```ts
app.post("/webhooks/dugble", async (request, response) => {
    // Signature verification will be documented with the public webhook release.
    const event = request.body;

    if (await eventStore.has(event.id)) {
        return response.sendStatus(200);
    }

    await eventStore.save(event.id, event);

    switch (event.type) {
        case "email.delivered":
            await markEmailDelivered(event.data.id);
            break;
        case "email.bounced":
            await suppressBouncedAddress(event.data.to);
            break;
        case "sms.delivered":
            await markSmsDelivered(event.data.id);
            break;
    }

    response.sendStatus(200);
});
```

Do not deploy signature verification based on guessed header names or algorithms. Dugble will publish the signing scheme and test tooling before outgoing webhooks are enabled.

## Current alternative

Until outgoing webhooks are available, retrieve message state directly:

- `GET /emails/{message_id}` for email
- `GET /sms/{message_id}` for SMS
- `POST /sms/{message_id}/sync-status` to request an SMS provider status refresh
