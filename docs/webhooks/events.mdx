<Warning>
    This is a preview of the planned outgoing webhook contract.
    Customer-configurable webhooks are not generally available yet.
</Warning>

Event types use a resource and lifecycle name, such as `email.delivered` or `sms.failed`.

## Common envelope

The planned envelope includes a stable event ID, an event type, a creation time, and resource data:

```json
{
    "id": "evt_01J2YQ3M6K4D5A7N8P9R0S1T2V",
    "type": "email.delivered",
    "created_at": "2026-07-26T12:01:10Z",
    "data": {
        "object": "email",
        "id": "49a3999c-0ce1-4ea6-ab68-afcd6dc2e794",
        "last_event": "delivered"
    }
}
```

Treat unknown fields and event types as forward-compatible additions. Do not fail an entire endpoint because it receives an event your application does not use.

## Email events

| Event              | Meaning                                     | Suggested action                                     |
| ------------------ | ------------------------------------------- | ---------------------------------------------------- |
| `email.queued`     | Dugble accepted the email for delivery.     | Store the Dugble message ID.                         |
| `email.processing` | Delivery processing started.                | Usually no action is required.                       |
| `email.submitted`  | The provider accepted the message.          | Mark the message as sent from your application.      |
| `email.delivered`  | The recipient server reported delivery.     | Mark the notification delivered.                     |
| `email.delayed`    | Delivery was temporarily delayed.           | Keep waiting and optionally show a delayed state.    |
| `email.bounced`    | The recipient server rejected the message.  | Review or suppress the recipient address.            |
| `email.complained` | The recipient reported the message as spam. | Suppress non-essential mail to the recipient.        |
| `email.rejected`   | The message was rejected before delivery.   | Inspect sender, recipient, and policy configuration. |
| `email.failed`     | Dugble could not complete delivery.         | Record the failure and decide whether to retry.      |
| `email.canceled`   | A scheduled email was canceled.             | Mark the scheduled operation canceled.               |

## SMS events

| Event             | Meaning                                      | Suggested action                                            |
| ----------------- | -------------------------------------------- | ----------------------------------------------------------- |
| `sms.queued`      | Dugble accepted the SMS for delivery.        | Store the Dugble message ID.                                |
| `sms.processing`  | Delivery processing started.                 | Usually no action is required.                              |
| `sms.submitted`   | The provider accepted the SMS.               | Mark the message submitted.                                 |
| `sms.sent`        | The provider reported that the SMS was sent. | Continue waiting for final delivery when supported.         |
| `sms.delivered`   | The provider reported delivery.              | Mark the notification delivered.                            |
| `sms.undelivered` | The provider could not deliver the SMS.      | Verify the destination number before retrying.              |
| `sms.rejected`    | The provider rejected the SMS.               | Review sender ID, content, and destination rules.           |
| `sms.expired`     | The provider's delivery window expired.      | Decide whether the message is still useful before retrying. |
| `sms.failed`      | Dugble could not complete delivery.          | Record the failure and review any refund state.             |
| `sms.canceled`    | A scheduled SMS was canceled.                | Mark the operation canceled and reconcile its refund.       |

## Idempotent handling

Your endpoint should:

1. Verify the webhook signature after the signing contract is published.
2. Store the event ID with a unique constraint.
3. Acknowledge duplicate IDs without repeating side effects.
4. Queue application work and respond quickly.
5. Log unknown event types rather than returning an error.
